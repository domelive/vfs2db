# Databases

This folder contains pre-built SQLite databases used for testing and demonstrating **vfs2db**.
Each database targets different features and stress levels of the FUSE driver.

---

## How to (Re)generate the Databases

All generator scripts are located in the project root. They only require Python 3 with the
built-in `sqlite3` module — no extra dependencies.

```bash
# From the project root:

# 1. Basic demo database (small, ideal for a quick tour)
python3 initdb.py
mv test.db databases/

# 2. Full stress-test database (many tables, large data, FK chains)
python3 generate_stress_db.py databases/stress_test.db

# 3. Massive single-table database (63 000 rows + huge BLOBs)
python3 monster2.py
mv massive_legend.db databases/

# 4. Complex schema database (wide table, deep FK chain, large BLOBs)
python3 monsterdb.py
mv stress_test.db databases/complex_schema.db
```

> **Tip:** every generator is deterministic (fixed seed or fixed data), so you can
> regenerate an identical database at any time.

## Detailed Schema Descriptions

### `test.db` — Basic Demo

Generated by **`initdb.py`**. A minimal relational database designed to showcase core
vfs2db features: composite primary keys, composite foreign keys, and FK-chain traversal.

| Table     | Columns                                                                                   | Records | Notes                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------- | ------- | -------------------------------------------------------------------------------------------------------- |
| `users`   | `name` TEXT, `surname` TEXT, `email` TEXT                                                 | 4       | **Composite PK** `(name, surname)`. One record has a ~50 MB email field (cache stress). `STRICT` mode.   |
| `orders`  | `id` INTEGER PK, `product_name` TEXT, `price` REAL, `user_name` TEXT, `user_surname` TEXT | 4       | **Composite FK** `(user_name, user_surname) → users(name, surname)`. `ON DELETE CASCADE`. `STRICT` mode. |
| `history` | `id` INTEGER PK, `order_id` INTEGER                                                       | 4       | **Simple FK** `order_id → orders(id)`. `ON DELETE CASCADE`. `STRICT` mode.                               |

**FK graph:**

```
history.order_id ──→ orders.id
orders.(user_name, user_surname) ──→ users.(name, surname)
```

**Filesystem example:**

```
mountpoint/
├── users/
│   ├── 1/                    # rowid 1 → Alice Smith
│   │   ├── name              # "Alice"
│   │   ├── surname           # "Smith"
│   │   └── email             # "alice@example.com"
│   └── ...
├── orders/
│   ├── 1/
│   │   ├── id                # "1"
│   │   ├── product_name      # "Laptop"
│   │   ├── price             # "1200.0"
│   │   ├── user_name    →    ../../users/1/   (symlink)
│   │   └── user_surname →    ../../users/1/   (symlink)
│   └── ...
└── history/
    ├── 1/
    │   ├── id                # "1"
    │   └── order_id     →    ../../orders/1/  (symlink)
    └── ...
```

### `stress_test.db` — Comprehensive Stress Test

Generated by **`generate_stress_db.py`** (seed: `42`). Designed to exercise **every**
driver feature simultaneously.

#### Core Tables

| Table         | Columns                                                                                       | Records | FK targets                                                             | Notes                                                       |
| ------------- | --------------------------------------------------------------------------------------------- | ------- | ---------------------------------------------------------------------- | ----------------------------------------------------------- |
| `users`       | `id` PK, `username`, `email`, `full_name`, `bio`, `created_at`, `age`, `balance`, `is_active` | 1 000   | —                                                                      | Base table. 15% NULLs on nullable columns.                  |
| `categories`  | `id` PK, `name`, `description`, `parent_id`                                                   | 30      | **Self-referencing** FK `parent_id → categories(id)`                   | 5 roots + 25 subcategories.                                 |
| `products`    | `id` PK, `name`, `description`, `price`, `stock`, `category_id`, `created_by`, `updated_by`   | 1 000   | `category_id → categories`, `created_by → users`, `updated_by → users` | Multiple FKs to different tables.                           |
| `orders`      | `id` PK, `user_id`, `order_date`, `status`, `total_amount`, `shipping_address`, `notes`       | 1 000   | `user_id → users`                                                      | Status enum: pending/confirmed/shipped/delivered/cancelled. |
| `order_items` | `id` PK, `order_id`, `product_id`, `quantity`, `unit_price`, `discount`                       | ~3 000  | `order_id → orders`, `product_id → products`                           | Junction table, 1–5 items per order.                        |

#### Type & Cache Testing Tables

| Table          | Columns                                                                                        | Records | Notes                                                                                        |
| -------------- | ---------------------------------------------------------------------------------------------- | ------- | -------------------------------------------------------------------------------------------- |
| `all_types`    | `id` PK, `int_val` INTEGER, `real_val` REAL, `text_val` TEXT, `blob_val` BLOB, `null_val` TEXT | 100     | Every SQLite type in one table. `null_val` is always `NULL`. Ideal for `getxattr user.type`. |
| `large_data`   | `id` PK, `name`, `size_category`, `large_text`, `created_at`                                   | 50      | Text fields of 64 KB, 256 KB, 512 KB, and 1 MB. Tests chunked reads and LRU cache eviction.  |
| `binary_data`  | `id` PK, `filename`, `mime_type`, `file_size`, `data` BLOB, `checksum`                         | 30      | BLOBs of 1 KB, 10 KB, and 100 KB. Tests binary data handling.                                |
| `many_columns` | `id` PK, `col_000`…`col_048` (50 total)                                                        | 50      | Mixed INTEGER/REAL/TEXT columns. Tests `readdir` with many entries.                          |

#### FK Chain Tables

Three independent chains of depth 4:

```
chain0_level0 ←── chain0_level1 ←── chain0_level2 ←── chain0_level3
chain1_level0 ←── chain1_level1 ←── chain1_level2 ←── chain1_level3
chain2_level0 ←── chain2_level1 ←── chain2_level2 ←── chain2_level3
```

Each table has 100 records. The `parent_id` column in each level is a FK to the previous
level's `id`. Tests deep symlink resolution.

#### Auxiliary Tables

| Table           | Columns                                                                                                                   | Records | Notes                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------- | ------- | ----------------------------------------------------- |
| `regions`       | `id` PK, `country_code`, `region_code`, `name`                                                                            | 8       | Has a `UNIQUE(country_code, region_code)` constraint. |
| `locations`     | `id` PK, `name`, `region_id`, `latitude`, `longitude`                                                                     | 200     | FK `region_id → regions(id)`.                         |
| `special_names` | `id` PK, `"Column With Spaces"`, `"column_with_underscore"`, `"MixedCaseColumn"`, `"123_starts_with_number"`, `"ALLCAPS"` | 50      | Tests path parsing with unusual column names.         |
| `empty_table`   | `id` PK, `name`, `value`                                                                                                  | **0**   | Edge case: `readdir` on empty table.                  |
| `single_record` | `id` PK, `important_data`, `timestamp`                                                                                    | **1**   | Edge case: single-record table.                       |

### `massive_legend.db` — High Row-Count Benchmark

Generated by **`monster2.py`**.

| Table         | Columns                                                                                         | Records | Notes                                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------- |
| `metrics`     | `id` PK AUTOINCREMENT, `device_id` TEXT, `temperature` REAL, `status` TEXT, `timestamp` INTEGER | 63 000  | Simulated IoT sensor data. `device_id` in range `DEV-1`…`DEV-1000`. Status is `"OK"` or `"WARNING"` (threshold: 80°). |
| `heavy_files` | `id` PK AUTOINCREMENT, `filename` TEXT, `content` BLOB                                          | 2       | Row 1: 10 MB binary BLOB (`big_10mb.bin`). Row 2: ~20 MB repeated text (`log_huge.txt`).                              |

**Primary use case:** benchmarking `readdir` performance on large directories (63 000
entries) and testing cache alignment with very large file reads.

### `complex_schema.db` — Extreme Schema Stress

Generated by **`monsterdb.py`**.

| Table                            | Columns                                                                      | Records | Notes                                                                                                                                                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `users`                          | `id` PK AUTOINCREMENT, `uuid` TEXT UNIQUE, `username`, `email`, `created_at` | 10 000  | Base identity table.                                                                                                                                                                                               |
| `org_chart`                      | `employee_id` PK, `manager_id`, `title`                                      | —       | **Self-referencing double FK**: both `employee_id` and `manager_id` reference `users(id)`. Models an organizational hierarchy.                                                                                     |
| `wide_metrics`                   | `id` PK, `user_id`, `col_0`…`col_1899`                                       | 100     | **1 902 columns total.** FK `user_id → users`. Tests extreme `readdir` (1 900+ files per record directory).                                                                                                        |
| `large_assets`                   | `id` PK, `user_id`, `asset_name`, `payload` BLOB, `meta_text` TEXT           | 1       | `payload`: 10 MB of null bytes. `meta_text`: 5 MB of `'A'` characters. FK `user_id → users`.                                                                                                                       |
| `chain_level_1`…`chain_level_10` | `id` PK, `parent_ref`, `info`                                                | 1 each  | 10-level deep FK cascade: `chain_level_1.parent_ref → users(id)`, `chain_level_2.parent_ref → chain_level_1(id)`, …, `chain_level_10.parent_ref → chain_level_9(id)`. All with `ON DELETE CASCADE`. `STRICT` mode. |

**FK cascade graph:**

```
users ←── org_chart.employee_id
users ←── org_chart.manager_id
users ←── wide_metrics.user_id
users ←── large_assets.user_id
users ←── chain_level_1 ←── chain_level_2 ←── ... ←── chain_level_10
```

## Inspecting a Database Manually

```bash
sqlite3 databases/test.db
```

Useful commands inside the SQLite shell:

```sql
.tables                          -- list all tables
.schema <table>                  -- show CREATE TABLE statement
PRAGMA table_info(<table>);      -- list columns with types
PRAGMA foreign_key_list(<table>);-- show foreign key definitions
SELECT COUNT(*) FROM <table>;    -- row count
SELECT * FROM users LIMIT 5;    -- quick data peek
```

## Filesystem Mapping Reminder

```
mountpoint/
└── <table>/
    └── <rowid>/
        ├── <column>          ← regular file  (read/write the cell value)
        └── <fk_column>  →   ../../<target_table>/<target_rowid>/  ← symlink
```

usage examples.
